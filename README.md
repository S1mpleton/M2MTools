# M2MTools Lite

Упрощённый редактор вариантов: хранит **упорядоченную реакцию**, а не автомат.
Разработка Lite ведётся в ветке `Lite`; полная версия остаётся в `Codex`.

## Ввод варианта

1. Выберите номер и направление преобразования.
2. Задайте **отдельно для Мили и Мура** количество состояний, входных и выходных
   сигналов. Состояний — от 1 до 999999; каждого вида сигналов — от 1 до 10.
3. Заполните реакцию слева направо. Каждый столбец — один такт:
   - верхняя строка: ровно один вход `x0`…`x9`;
   - нижняя: выходы `y0`…`y9` через запятую, например `y3,y0,y2`;
   - пустая нижняя ячейка или `-` означает отсутствие выхода.
4. При необходимости прикрепите изображение задания: кнопкой «Загрузить изображение»,
   нажатием на область предпросмотра или перетаскиванием одного файла.
   Поддерживаются изображения PNG, JPEG, BMP, WebP при наличии соответствующего
   плагина Qt; размер — до 10 МБ. Кнопка «Удалить изображение» убирает вложение.
5. Сохраните вариант. `Ctrl+S` также сохраняет; `Ctrl+N` создаёт новый вариант.

Нельзя повторять выход внутри одного такта, вводить `x10`, `y10`, несколько
входов в ячейку или пропускать вход между заполненными тактами. Пустые столбцы
справа — свободное место и не сохраняются. При запуске и создании нового варианта
таблица содержит один столбец. `Enter` (включая цифровую клавиатуру) вставляет
один такт сразу после выбранного столбца. Во время редактирования сначала
сохраняется корректное значение ячейки; незавершённый ввод не создаёт такт.
Ввод сам по себе не добавляет столбцы. Кнопки позволяют вставить или удалить
такт; после удаления последнего остаётся один пустой столбец.

Количество сигналов — размер алфавита, а не максимальный индекс: один сигнал
может называться `x9`. Реакция может использовать часть алфавита, но не больше
сигналов, чем заявлено в любом из двух блоков. По конечной реакции невозможно
определить все состояния или доказать эквивалентность автоматов; количества
состояний задаёт автор задания.

Имена состояний, начальное состояние и переходы не вводятся. Изображение
необязательно: варианты без него остаются допустимыми. Оно сохраняется внутри
базы и архива, поэтому исходный файл не нужен при повторном открытии варианта.
Новый вариант очищает также изображение. Загрузка неподдерживаемого файла
не удаляет уже прикреплённую картинку.
Список вариантов поддерживает загрузку, удаление, фильтрацию и обмен номерами.
Изменения перед закрытием или сменой варианта можно сохранить или отменить.
Интерфейс использует палитру ОС и встроенные векторные значки, доступные в том
числе в Windows без темы значков. Языки интерфейса: русский и английский.

## Хранение и совместимость

Рабочая база — `variants-lite.db` в текущем каталоге:

- `Variants`: номер, направление и шесть количеств;
- `ReactionSteps`: `variant_id`, `position` (с нуля), `input`, `outputs_json`;
- `VariantImages`: необязательное вложение, `variant_id`, `data` (BLOB), `file_name`;
- `LiteMetadata`: версия схемы (1).

При открытии существующей базы Lite таблица вложений добавляется автоматически
без изменения вариантов и порядка тактов. Удаление варианта удаляет его вложение.

Порядок тактов задаётся ключом `(variant_id, position)` и обязательным
`ORDER BY position ASC` при чтении. Выходы хранятся JSON-массивом: `y3,y0,y2`
не превратится в `y0,y2,y3`. Повторяющиеся входы и одинаковые такты сохраняются.
Пропущенная позиция или некорректный формат при чтении считаются ошибкой.

Экспорт/импорт: `*.m2m`, заголовок `M2MLITE1`, AES-256-GCM, PBKDF2-SHA256,
случайные соль и nonce. Сохранена схема ключа, управляемого приложением,
из текущей полной версии; пароль не запрашивается. Это защита переносимого
файла от изменения, а не секрет от пользователя, имеющего исходный код.

Расшифрованный JSON: `format: "M2MToolsLite"`, `version: 1`, `variants` — массив
объектов с полями `number`, `type`, `mealy`, `moore`, `reaction`. В `mealy` и
`moore` находятся `states`, `inputs`, `outputs` (числа). В `reaction` — массив
`{ "input": "x2", "outputs": ["y3", "y0"] }` в исходном порядке.
Необязательное поле `image` содержит `{ "fileName": "Задание.png", "data": "…" }`,
где `data` — исходные байты файла в Base64. Старые архивы без этого поля
по-прежнему принимаются. Изображение проверяется при загрузке и импорте.

Импорт сначала проверяет весь архив, затем заменяет базу одной транзакцией.
При ошибке записи или проверки база остаётся прежней. Экспорт записывается
атомарно через `QSaveFile`.

Расширение экспорта/импорта — `.m2m`. Формат определяется заголовком внутри
файла. Уже созданные `.m2mlite` можно переименовать в `.m2m`: содержимое архива
не менялось.

Полные базы `variants.db` и архивы полной версии не преобразуются автоматически:
они не хранят исходный порядок реакции и оба набора количеств. Текущая версия
**M2MConvertor из Codex пока не читает формат Lite**; её адаптация к заданиям
по реакции — отдельное изменение протокола комплекса.

## Структура и проверка

- `core/reactionvariant.*`: данные, проверка, JSON-контракт;
- `data/`: схема, репозиторий, транзакции и операции над вариантами;
- `core/variantarchive.*`: шифрование и формат архива;
- `ui/widgets/reactiontable.*`: двухстрочный редактор;
- `core/variantimage.*`: вложение, проверка изображения и сериализация;
- `ui/widgets/variantimagepanel.*`: загрузка, предпросмотр и удаление изображения;
- `validation/reactionvalidator.*`: валидаторы редактирования;
- `ui/appicons.*`: векторные значки с цветами ОС.

Требуются CMake 3.19+, C++17, OpenSSL 1.1.1+, Qt 6.5+ (Widgets, Sql,
LinguistTools; Test для тестов).

```bash
cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build
ctest --test-dir build --output-on-failure
```

Тесты проверяют границы валидаторов, оба блока количеств, порядок после
повторного открытия SQLite и зашифрованного экспорта/импорта, откат ошибок,
отказ от баз полной версии, обновление старой базы Lite, перенос изображений
без изменения байтов, загрузку/удаление/перетаскивание через UI, ввод/сохранение
реакции и уникальность значков меню.

## Формы Qt Designer и цели сборки

Главное окно описано в `ui/mainwindow.ui`, список вариантов — в
`ui/variantslist.ui`, блок изображения — в `ui/widgets/variantimagepanel.ui`.
Их можно открыть в Qt Creator / Designer и менять
расположение, подписи, отступы, размеры, меню и кнопки. `objectName` используется
обработчиками C++, поэтому при переименовании элемента нужно обновить обращения
к нему. `ReactionTable` и `WrappingLabel` — promoted widgets на базе
`QTableWidget` и `QLabel`: в Designer они отображаются через базовые классы,
поведение подключается при сборке. `VariantImagePanel` аналогично
подключён как promoted widget на базе `QGroupBox`; его содержимое редактируется
в отдельной форме `variantimagepanel.ui`. Сгенерированные `ui_*.h` редактировать не нужно.

Окно впервые открывается с минимальным размером, который вычисляет layout по
содержимому, текущему шрифту и стилю ОС. Высота таблицы учитывает заголовки,
строки и полосу прокрутки; подсказки резервируют всю высоту перенесённого текста.

Цели CMake — части одного проекта:

- `M2MCore` — статическая библиотека: модель реакции, проверки, SQLite, архивы;
- `M2MUi` — статическая библиотека: формы и поведение интерфейса;
- `M2MTools` — запускаемое приложение, связывающее обе библиотеки;
- `M2MTests` — отдельный исполняемый файл автоматических проверок.

Так интерфейс отделён от работы с данными, а приложение и тесты используют один
и тот же код библиотек. Библиотеки встраиваются в приложение при компоновке;
пользователю не нужно запускать Core или Ui. Для сборки только приложения:
`cmake --build build --target M2MTools`. Для отключения тестовой цели при
конфигурации: `-DBUILD_TESTING=OFF`.
