# Облачная среда M2MTools

Скрипты воспроизводят проверенную среду Codex: Debian 13 amd64, GCC 14,
CMake 3.31.6, Ninja 1.12.1, OpenSSL 3 и Qt 6.8.2 с Widgets,
LinguistTools, Sql и SQLite.
Версии приведены по результатам проверки; APT использует актуальные пакеты
Debian trixie с проверкой подписей индекса и контрольных сумм.
Root и sudo не нужны. Секреты и внешние сервисы не требуются.

Ожидается существующий checkout в `/workspace/M2MTools`. Облачные задачи
уже изолированы; создавать Git worktree следует только по явному запросу.

## Установка и проверка

```bash
cd /workspace/M2MTools
bash tools/cloud-setup/bootstrap.sh
```

Bootstrap размещает небольшие входные файлы в `/workspace/.cloud-setup`,
загружает и распаковывает зависимости в локальный sysroot, собирает Debug
и выполняет функциональные проверки. Существующие одинаковые файлы
используются повторно; при различиях скрипт останавливается, чтобы их
можно было согласовать вручную.

В Git хранятся только скрипты, настройки и исходники smoke-проверки.
Пакеты, sysroot, сборки, кэш и базы остаются в `/workspace/.cloud-setup`.
Сохраните этот каталог целиком в снимке среды. Процессы и переменные
окружения нужно активировать заново после восстановления.

## Разработка и запуск

```bash
source /workspace/.cloud-setup/env.sh
cmake --build /workspace/.cloud-setup/build --target M2MTools --parallel 2
cmake --build /workspace/.cloud-setup/smoke-build --parallel 2
ctest --test-dir /workspace/.cloud-setup/smoke-build --output-on-failure
python3 /workspace/.cloud-setup/check-startup.py
bash /workspace/.cloud-setup/start.sh
```

`start.sh` запускает приложение из `/workspace/.cloud-setup/run`, где
оно хранит относительную `variants.db`. По умолчанию используется Qt
`offscreen`. Видимый рабочий стол и веб-предпросмотр не настраиваются.
Для работы с кодом постоянно запущенное приложение не требуется.

## Что проверено

- Полная Debug-сборка, генерация MOC/UIC/RCC и перевода.
- Один CTest smoke-тест: повторное создание и миграция старой схемы,
  двусторонняя синхронизация реакции, изображения, операции с номерами,
  зашифрованный BazaVar, round-trip автоматов Mealy/Moore и современный GUI.
- Два запуска настоящего приложения через `start.sh`, проверка схемы
  и целостности SQLite, остановка и повторный запуск.
- Повторное выполнение установки с использованием существующей сборки.

Smoke-тест использует объекты текущей сборки приложения и временную базу.
Сначала пересобирайте приложение, затем smoke-тест.

## Ограничения исходного проекта

Два заголовка presenter подключают `core/Result.h`, хотя файл называется
`core/result.h`. На Linux обычная сборка из-за этого завершается ошибкой.
Установка задаёт `-DCMAKE_CXX_FLAGS=-I/workspace/.cloud-setup/include`,
где внешний `core/Result.h` перенаправляет подключение к настоящему файлу.
Совместимость обеспечивается без дополнительного изменения этих заголовков.

Отсутствие необязательных XKB development-файлов не блокирует проверенный
offscreen-сценарий. Исходный проект не регистрирует собственные CTest-тесты.
Не запускайте цель `lupdate` при настройке: она меняет отслеживаемый
файл перевода. Собирайте цель `M2MTools`.

Публикация среды выполняется отдельно в интерфейсе Codex; скрипты её
не выполняют. Проверка восстановления в новой задаче ещё не проводилась.
